# examples/ — integrated controller + trajectory generator suite

This directory ships one executable (and one Python twin) per
`(controller, trajectory generator)` pair wired against the shared
[`WaypointsSimulator`](framework/include/framework/waypoints_simulator.hpp).
Every combination writes the same 44-column CSV so the runs can be compared
directly with the scripts in [`../scripts/`](../scripts/).

The goal of this README is operational: document the **two interfaces**
([`IController`](#the-icontroller-interface) and
[`ITrajectoryGenerator`](#the-itrajectorygenerator-interface)) that every
example implements, and show — step by step — how to plug a new controller or
a new reference generator into the same harness.

## Layout

```
examples/
├── framework/                   # IController, ITrajectoryGenerator, WaypointsSimulator (C++ + Python)
├── adapters/                    # Concrete implementations of both interfaces
│   ├── controllers/{pid_geometric, mpc_position, mpc_trajectory}/
│   └── trajectory_generators/{waypoint_reference, jerk_limited, gcopter, dynamic}/
├── examples/                    # One main per (controller × generator) × {C++, Python}
│   ├── <controller>_<generator>/
│   │   ├── CMakeLists.txt
│   │   ├── run_example.cpp
│   │   └── run_example.py
│   └── _common/                 # Shared Python CLI helpers for the 12 twins
├── utils/                       # CsvLogger, plot_results.py, compute_metrics.py
├── acados_position_mpc/         # Generated by ../generate.sh
└── acados_trajectory_mpc/       # Generated by ../generate.sh
```

## Data flow

```
     ┌────────────────────────┐
     │ ITrajectoryGenerator   │   evaluate(t) → ReferenceSample
     │ (adapter)              │   ─────────────┐
     └────────────────────────┘                │
                                               ▼
                                   ┌─────────────────────────────┐
                                   │    WaypointsSimulator       │
                                   │    (framework)              │
                                   │                             │
                                   │  t, state ─► traj_gen.update│
                                   │  t+i·dt   ─► traj_gen.evaluate
                                   │  horizon  ─► ctrl.compute   │
                                   └──────────────┬──────────────┘
                                                  │ ControlCommand
                                                  ▼
                                        ┌───────────────────┐
                                        │ mav_simulator     │ RATES mode
                                        │ (500 Hz INDI /    │ thrust + ω_body
                                        │  1000 Hz physics) │
                                        └───────────────────┘
                                                  │ state
                                                  └─► back to controller
```

Nested rates, all declared in `configs/simulation/config_example.yaml`:

| Loop | Typical rate | Field |
|------|--------------|-------|
| Outer controller (MPC or PID) | 100 Hz | `mpc_dt` / `pid_dt` |
| INDI + IMU                    | 500 Hz | `controller_dt` |
| Physics                       | 1000 Hz | `model_dt` |

The outer `ControlCommand` is held constant (zero-order hold) over the inner
INDI sub-steps — the same pattern used on real hardware.

Units and frames across the whole stack:

- Position, velocity, acceleration, yaw: **world frame**, SI units.
- Body rates in `ControlCommand`: **body frame**, `rad/s`.
- Thrust in `ControlCommand`: collective, `N`.
- Quaternions: scalar-first `(qw, qx, qy, qz)`.

## The `IController` interface

Defined in
[`framework/include/framework/controller_base.hpp`](framework/include/framework/controller_base.hpp)
(C++) and
[`framework/python/mpc_examples_framework/controller_base.py`](framework/python/mpc_examples_framework/controller_base.py)
(Python).

```cpp
class IController {
public:
  virtual void initialize(const mav_model::State& initial_state,
                          const ExampleConfig& example_cfg) = 0;
  virtual int    referenceHorizonSize() const = 0;   // N+1 samples
  virtual double referenceHorizonDt()   const = 0;   // [s]
  virtual double controlPeriod()        const = 0;   // [s] outer loop
  virtual ControlCommand computeCommand(const mav_model::State& state,
                                        const std::vector<ReferenceSample>& refs) = 0;
  virtual ReferenceFieldMask requiredReferenceFields() const = 0;
  virtual const std::string& name() const = 0;
  virtual double lastSolveTimeMicros() const = 0;
};
```

Python mirror uses snake-case (`reference_horizon_size()`,
`compute_command(...)`, `required_reference_fields()`, …) and abstract base
class `IController` inheriting from `abc.ABC`.

Shipped implementations:

| Adapter | Required fields | Horizon size | Notes |
|---------|-----------------|--------------|-------|
| [`PidGeometricController`](adapters/controllers/pid_geometric/)    | `Position`                          | 1     | Cascaded position → velocity PID + geometric inner controller (`mav_controllers`). |
| [`MpcPositionController`](adapters/controllers/mpc_position/)      | `Position`                          | 1     | acados position MPC; adapter expands the single position into `N+1` stages internally using `max_speed` and the horizon dt. |
| [`MpcTrajectoryController`](adapters/controllers/mpc_trajectory/)  | `Position + Velocity + Acceleration` | N+1 | acados trajectory MPC; consumes a full feedforward horizon sampled from the generator. |

`referenceHorizonSize()` is the contract `WaypointsSimulator` uses to size the
vector passed to `computeCommand`. `referenceHorizonDt()` multiplied by
`(referenceHorizonSize() - 1)` must not exceed the generator's reachable time
window.

## The `ITrajectoryGenerator` interface

Defined in
[`framework/include/framework/trajectory_generator_base.hpp`](framework/include/framework/trajectory_generator_base.hpp)
and
[`framework/python/mpc_examples_framework/trajectory_generator_base.py`](framework/python/mpc_examples_framework/trajectory_generator_base.py).

```cpp
class ITrajectoryGenerator {
public:
  virtual void initialize(const std::vector<Eigen::Vector3d>& waypoints,
                          const mav_model::State& initial_state,
                          const ExampleConfig& example_cfg) = 0;
  virtual void             update(double t, const mav_model::State& state) = 0;
  virtual ReferenceSample  evaluate(double t) const = 0;
  virtual bool             isFinished(double t) const = 0;
  virtual int              currentWaypointIndex() const = 0;
  virtual ReferenceFieldMask providedReferenceFields() const = 0;
  virtual const std::string& name() const = 0;
};
```

Python mirror: `ITrajectoryGenerator` abstract base with
`provided_reference_fields()`, `is_finished(t)`, `current_waypoint_index()`.

`update(t, state)` is called once per outer control step before sampling; it's
the hook for generators that re-plan on-line (dynamic re-optimisation,
waypoint advance). `evaluate(t)` is called `referenceHorizonSize()` times per
step at times `[t, t + dt, …, t + N·dt]` and must be pure (no state mutation).

Shipped implementations:

| Adapter | Provided fields | Notes |
|---------|-----------------|-------|
| [`WaypointReferenceGenerator`](adapters/trajectory_generators/waypoint_reference/) | `Position`                            | Piecewise-constant target; advances when the drone enters `reach_threshold`. Clamps emitted positions to within `d_max` of the current state to avoid jumps. |
| [`JerkLimitedGenerator`](adapters/trajectory_generators/jerk_limited/)             | `Position + Velocity + Acceleration`  | PX4-style 3-phase S-curve per axis with `max_acc`/`max_jerk` bounds. Speed comes from `ExampleConfig.max_speed`. Integrated forward by `update(t, state)`. |
| [`GcopterGenerator`](adapters/trajectory_generators/gcopter/)                      | `Position + Velocity + Acceleration`  | GCOPTER minimum-snap polynomial trajectory with polytope-SFC corridor. Optimised **once** in `initialize()`; `evaluate(t)` samples the cached polynomial. |
| [`DynamicTrajectoryGenerator`](adapters/trajectory_generators/dynamic/)            | `Position + Velocity + Acceleration`  | Async polynomial trajectory (thread-based). Supports on-line waypoint replan. |

## Common types

From [`framework/include/framework/types.hpp`](framework/include/framework/types.hpp) (C++) and
[`framework/python/mpc_examples_framework/types.py`](framework/python/mpc_examples_framework/types.py) (Python).

```cpp
enum class ReferenceField : uint32_t {
  kPosition     = 1u << 0,
  kVelocity     = 1u << 1,
  kAcceleration = 1u << 2,
};

struct ReferenceSample {
  Eigen::Vector3d position;      // [m]    world
  Eigen::Vector3d velocity;      // [m/s]  world
  Eigen::Vector3d acceleration;  // [m/s²] world
  double          yaw;           // [rad]  absolute heading
};

struct ControlCommand {
  double          thrust_n;      // [N]    collective
  Eigen::Vector3d angular_rate;  // [rad/s] body
};
```

`ReferenceFieldMask` is a bitmask of `ReferenceField`. Helpers:

- `makeMask({ReferenceField::kPosition, ReferenceField::kVelocity})`
- `hasField(mask, ReferenceField::kPosition)`

## Compatibility check

When `WaypointsSimulator` is constructed it compares the controller's
`requiredReferenceFields()` against the generator's `providedReferenceFields()`.
If required ⊄ provided, the following warning is printed to `stderr`:

```
[WaypointsSimulator] Warning: generator '<gen>' does not provide fields
required by controller '<ctrl>': <list>. Missing fields will be held at zero;
controller may not converge as expected.
```

The simulation still runs, with missing fields zeroed in every
`ReferenceSample`. This is intentional — running `MpcTrajectoryController`
against `WaypointReferenceGenerator` (velocity/accel = 0) is a useful
degradation study, but any ungracefully missing field shows up in the log.

## Adding a new controller

Step-by-step; replace `<name>` with the controller's short snake-case
identifier (e.g. `mpc_rate`, `nmpc`, `lqr`).

1. **C++ adapter**
   - `examples/adapters/controllers/<name>/include/adapters/controllers/<name>_controller.hpp`: a class that `public IController`.
   - `examples/adapters/controllers/<name>/src/<name>_controller.cpp`: the implementation. Follow the layout of
     [`mpc_position_controller.hpp`](adapters/controllers/mpc_position/include/adapters/controllers/mpc_position_controller.hpp) (headers) and
     [`mpc_position_controller.cpp`](adapters/controllers/mpc_position/src/mpc_position_controller.cpp) (source).
   - `examples/adapters/controllers/<name>/CMakeLists.txt`: copy the pattern from
     [`adapters/controllers/mpc_position/CMakeLists.txt`](adapters/controllers/mpc_position/CMakeLists.txt):
     ```cmake
     add_library(mpc_examples_adapter_<name> STATIC src/<name>_controller.cpp)
     target_include_directories(mpc_examples_adapter_<name> PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/include)
     target_link_libraries(mpc_examples_adapter_<name> PUBLIC
       mpc_examples_framework <your_upstream_library> mav_simulator yaml-cpp)
     target_compile_features(mpc_examples_adapter_<name> PUBLIC cxx_std_17)
     ```
   - Add `add_subdirectory(controllers/<name>)` to [`adapters/CMakeLists.txt`](adapters/CMakeLists.txt).

2. **Python mirror**
   - `examples/adapters/python/mpc_examples_adapters/controllers/<name>_controller.py`: a class that
     inherits from `mpc_examples_framework.IController`, mirroring the C++ interface with snake-case
     method names. Use
     [`mpc_position_controller.py`](adapters/python/mpc_examples_adapters/controllers/mpc_position_controller.py)
     as reference.
   - Export it from [`mpc_examples_adapters/controllers/__init__.py`](adapters/python/mpc_examples_adapters/controllers/__init__.py).

3. **Controller config**
   - New `configs/controllers/config_<name>.yaml` alongside the existing ones
     (see [`configs/controllers/config_mpc.yaml`](../configs/controllers/config_mpc.yaml) for a full example).
   - Expose `static Config loadConfigFromYaml(const std::string&)` in C++ and
     `classmethod load_config_from_yaml(cls, path: str)` in Python so the
     main program stays one-liner.

4. **Example mains** — create one per compatible trajectory generator
   under `examples/examples/<name>_<generator>/`:
   - `run_example.cpp`: copy
     [`examples/mpc_position_waypoints/run_example.cpp`](examples/mpc_position_waypoints/run_example.cpp)
     and swap in the new adapter headers.
   - `run_example.py`: copy the matching
     [`run_example.py`](examples/mpc_position_waypoints/run_example.py);
     `_common.parse_full_args` keeps the CLI identical.
   - `CMakeLists.txt`: copy
     [`mpc_position_waypoints/CMakeLists.txt`](examples/mpc_position_waypoints/CMakeLists.txt)
     and link the new `mpc_examples_adapter_<name>` target.

5. **Scripts**
   - Append `<name>` to the `CONTROLLERS` array in
     [`../scripts/run_all.sh`](../scripts/run_all.sh) and add a case in
     `controller_cfg()` pointing to `configs/controllers/config_<name>.yaml`.
   - Append `<name>` to the `COMBINATIONS` list in
     [`../scripts/compare_all.py`](../scripts/compare_all.py).

6. **Documentation**
   - Add a row to the table in [`../README.md`](../README.md) and the table
     at the top of this file.

## Adding a new trajectory generator

Structure mirrors the controller procedure. Replace `<name>` with the
generator's snake-case identifier (e.g. `bezier`, `minimum_snap`, `ros_topic`).

1. **C++ adapter**
   - Header implementing `ITrajectoryGenerator` under
     `examples/adapters/trajectory_generators/<name>/include/adapters/trajectory_generators/<name>_generator.hpp`.
   - Source under `examples/adapters/trajectory_generators/<name>/src/<name>_generator.cpp`.
   - Use
     [`jerk_limited_generator.hpp`](adapters/trajectory_generators/jerk_limited/include/adapters/trajectory_generators/jerk_limited_generator.hpp)
     as template when the generator integrates forward in `update(t, state)`;
     use
     [`gcopter_generator.hpp`](adapters/trajectory_generators/gcopter/include/adapters/trajectory_generators/gcopter_generator.hpp)
     when it pre-computes a polynomial in `initialize()`.
   - Declare `providedReferenceFields()` to match what `evaluate()` actually
     fills in. Fields left at their default zero value **must not** appear in
     the mask or controllers downstream will be misled.
   - `CMakeLists.txt` following the pattern in
     [`trajectory_generators/jerk_limited/CMakeLists.txt`](adapters/trajectory_generators/jerk_limited/CMakeLists.txt):
     ```cmake
     add_library(mpc_examples_adapter_<name> STATIC src/<name>_generator.cpp)
     target_include_directories(mpc_examples_adapter_<name> PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/include)
     target_link_libraries(mpc_examples_adapter_<name> PUBLIC
       mpc_examples_framework <your_upstream_library> mav_simulator yaml-cpp)
     target_compile_features(mpc_examples_adapter_<name> PUBLIC cxx_std_17)
     ```
   - Register in [`adapters/CMakeLists.txt`](adapters/CMakeLists.txt).

2. **Python mirror**
   - `examples/adapters/python/mpc_examples_adapters/trajectory_generators/<name>_generator.py`
     with a class inheriting from `mpc_examples_framework.ITrajectoryGenerator`.
     Reference:
     [`jerk_limited_generator.py`](adapters/python/mpc_examples_adapters/trajectory_generators/jerk_limited_generator.py).
   - Export from
     [`mpc_examples_adapters/trajectory_generators/__init__.py`](adapters/python/mpc_examples_adapters/trajectory_generators/__init__.py).

3. **Generator config**
   - `configs/generators/config_<name>.yaml`. Expose `loadConfigFromYaml` / `load_config_from_yaml` symmetric to controllers.

4. **Example mains**
   - One `examples/examples/<controller>_<name>/` per controller you want to
     combine with, following the patterns documented above.

5. **Scripts**
   - Append `<name>` to `GENERATORS` in
     [`../scripts/run_all.sh`](../scripts/run_all.sh) and add a case to
     `generator_cfg()`.
   - Append `<name>` to `COMBINATIONS` in
     [`../scripts/compare_all.py`](../scripts/compare_all.py).

## Running and analysing

```bash
./scripts/run_all.sh --lang=both                      # 24 CSVs in simulator_logs/
python3 scripts/compare_all.py --out /tmp/summary.csv # aggregate metrics table
python3 scripts/plot_all.py                           # per-run PNGs under simulator_logs/plots/
```

For a single run, the utilities accept the CSV directly:

```bash
python3 examples/utils/plot_results.py     -f simulator_logs/mpc_position_waypoints_log.csv
python3 examples/utils/compute_metrics.py  -f simulator_logs/mpc_position_waypoints_log.csv
```

The CSV schema (44 columns) is documented in the top-level
[`../README.md`](../README.md).
